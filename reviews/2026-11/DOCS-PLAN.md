# Documentation plan — tradebot fresh start

Plan for the parallel doc-writer agents. Machine-readable twin: `DOCS-PLAN.json` (same content; generated by `mkplan.py`, which also checks coverage and ownership).

- **Inputs:** the nine docs review reports (`reviews/docs-*.{md,json}`), `DOCS-HANDOFFS.json` (18 entries from the code units), and the docs as they stand at the **baseline commit `b8f0ca6`**. Docs have barely changed since the review (`ac10a6c`): only `.github/copilot-instructions.md` was corrected and `dev/tooling/src/tools/cold/legacy/` (with its README) was deleted. Code has changed a lot (about 80 commits), and more is still landing (prospector-walk, vault, router-pipe; there are uncommitted changes under services/catalog, catalog-ui, prospector and router).
- **This plan gives structure and ownership, not facts.** Every writer checks every claim against the current code. Review line numbers and suggested wordings are leads, not truth.
- **Coverage:** all 222 IMPLEMENT items of the nine docs reports are assigned except one (DPLT-12, blocked by a DEFER), and each assigned item has exactly one owning group. All 18 handoffs are assigned, written `<from>:<item_id>`. Each doc file has exactly one owner. Where an item spans files of several groups, it is assigned to one group, and the other groups' instructions name the part to apply in their own files.

## Common rules (every group)

1. CLAUDE.md is binding: dependency direction, venues are providers to everything, VOCABULARY depends on nothing, each subject has one home, only what is true today (plans only in `docs/planning/`), and a doc is about its own subject.
2. Verify against the **current** code at the time of writing. When the code contradicts a review item, the code wins.
3. Edit only the files your group owns. A change needed in another group's file goes into your report.
4. Docs only. You may change prose, comments in the config files you own, and docblocks in the source files you own. You may not change behaviour, configuration values or tests. Where a review item prescribes a code or config change, check whether a code unit has landed it. Describe the code as it is, and report any gap.
5. **Moves.** The destination group writes the content, reading the source at the baseline (`git show b8f0ca6:<path>`). The source group deletes its copy, leaving at most a one-line pointer. Neither group waits for the other. Carry over only what is still true.
6. **Links.** Link to a file, or to a heading listed under *Promised anchors*. Never link to code lines (`#L123`). Code docblocks point at docs by file, not by anchor. A pointer must not be needed to understand the doc that holds it. Run a link and anchor check on your files (`reviews/scratch/links.py` or an equivalent) before you finish.
7. Use the terms in *Terminology* below.
8. Do not act on DEFER items. Where a DEFER blocks a restructure, keep the current arrangement and fix accuracy only.
9. Every `services/*/README.md` gets one line, `Deployed by: <module or pack>` or `Deployed by: no module`, checked against the compose includes (DXC-23). The group that owns the README writes the line.
10. **Final report**, in this order:
    - items resolved;
    - items partly resolved or moot, with the reason;
    - code/doc gaps found;
    - changes needed in other groups' files.

## Terminology (decided here so groups can write in parallel)

- **vault** means the Parquet vault that stocker writes. The CSV store in `services/vault` is called *the vault service* wherever the two could be confused. It is not renamed, because DCOL-17 and DPLT-25 are deferred.
- **source** means archives, REST or WS. *origin* is used only as the `cold` CLI argument (the tree a command acts on); prose says *tree*. VOCABULARY gets one disambiguating *Origin* entry.
- **bucket** means only an S3 bucket.
  - The venue-wide `@` file is the *market bundle (`@`)*.
  - Stocker's time bucket is a *period*.
  - The catalog's `buckets` JSON field keeps its name and is described as the count of market-bundle files.
- **slice** means VOCABULARY's slice.
  - A lens is a *named selection*, never a "named slice".
  - Stocker's directory is a *vault slice*, defined once in STOCKER.md#path-convention.
  - Prospector's write queue is *the serial write queue*.
- **partition** means VOCABULARY's partition (slice × month). In prospector, a walk unit with a cursor and a `run` row is a *scope*, and a pass over a venue is a *job*.
- **reconciliation** means only prospector's `reconcile()` after a finished pass. The comparison against a venue's instrument listing is *the preamble*.
- **Shape**, **Table**, **Origin** and the `@` spelling of the market bundle are defined in VOCABULARY.md by the entry group. Other docs use these terms without redefining them.
- **Letter folder:** `F`, never `FL`.
